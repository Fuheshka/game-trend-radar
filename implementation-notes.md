# Implementation Notes: Game Trend Radar

> [!abstract] Паттерн ведения заметок реализации (Thariq / Anthropic Pattern)
> Документ фиксирует инженерные решения, технические компромиссы, ограничения внешних API и архитектурные развилки в процессе разработки.

---

## 1. Выбор архитектуры коллекторов данных

- **Проблема:** Браузерные движки (Puppeteer / Playwright) потребляют от 150 до 400 МБ памяти на каждый запуск, требуют бинарников Chromium и медленно стартуют в фоновых CLI задачах.
- **Решение:** Максимальный упор на легковесные прямые HTTP-запросы через нативный `fetch` (Node.js 20+).
  - *Roblox:* использование официального публичного Explore API (`apis.roblox.com/explore-api/v1/get-sort-content`), отдающего 100 игр с реальным CCU за ~300мс.
  - *Яндекс Игры:* парсинг SSR HTML каталога (`https://yandex.ru/games/`) через быстрые регулярные выражения и потоковый парсинг без загрузки тяжелых JS-бандлов.
  - *Poki:* парсинг HTML чарта `poki.com/en/popular`.
- **Компромисс:** Для YouTube Shorts в условиях сетевых ограничений и блокировок применяется отказоустойчивый режим (fallback-анализ метаданных и трендовых поисковых срезов без жесткого требования к постоянному стриму видео).

---

## 2. Скоринговая модель (Opportunity Score)

- **Почему линейный скоринг не работает:** Простая сумма баллов приводит к тому, что старые игры с миллионами установок (но перегретым рынком) получают высший приоритет, толкая разработчика в «красный океан».
- **Решение:** Дробно-рациональная формула, где в знаменателе стоит **Индекс насыщенности (Saturation Index)** и **Трудоемкость (Production Effort)**. Любой жанр с высокой конкуренцией или завышенной сложностью сборки резко штрафуется в итоговом рейтинге.

---

## 3. Версионирование и снимки рынка (Snapshots)

- Снимки сохраняются в `data/snapshots/snapshot-YYYY-MM-DD.json`.
- Это позволяет сравнивать дельту между замерами:
  - Какие игры выросли по онлайну за неделю.
  - Какие новинки ворвались в топ и сохраняют удержание.
  - Какие жанры теряют позиции.

---

## 4. Живое сканирование YouTube Shorts и детекция вирусных мемов

- **Двухуровневый сбор данных (Invidious + YouTube Data API v3):**
  - Приоритет отдается публичным инстансам Invidious (`inv.tux.pizza`, `invidious.nerdvpn.de` и др.), что исключает необходимость обязательной выдачи платных или лимитированных API-ключей Google Cloud.
  - При наличии `YOUTUBE_API_KEY` модуль автоматически задействует официальный YouTube Data API v3 (`search` + `videos.statistics`).
  - Реализован строгий тайм-аут запросов (`AbortController` на 6000мс) и автоматический перебор зеркал при сетевых ошибках или HTTP 5xx.
  - Бесшовный fallback на локальный курируемый датасет при полном отсутствии сети или блокировках.
- **Детекция вирусных сущностей:**
  - Библиотека регулярных выражений (`VIRAL_MEME_DEFINITIONS`) покрывает ключевые мета-тренды:
    - *Skibidi Toilet / Cameraman* (Roblox/Sandbox)
    - *The Amazing Digital Circus* (Pomni, Jax, Caine)
    - *Brainrot / Sigma / Rizz* (Only in Ohio, Mewing, Gigachad)
    - *Steal An Egg / Catch & Run* (Escape & incremental runner)
- **Расчет коэффициента вирусного ускорения (Viral Multiplier):**
  - Значение масштабируется от `1.0` (нейтрально) до `2.5` (сверхвирусный всплеск).
  - Учитывает частоту появления мемов в выборке и среднее число просмотров роликов.
  - Передается в `OpportunityScorer` для мультипликативного ускорения `velocityScore` и итогового скора перспективности жанра.

## 5. Стратегия полной автоматизации мониторинга (Zero-Maintenance)

- **Проблема зависимости от хардкода:** Зашивание регулярных выражений в код требует постоянного ручного вмешательства разработчика при появлении каждого нового интернет-мема.
- **Архитектурное решение (Спринт 6):**
  1. *YouTube Search Autocomplete API*: прямой опрос поисковых подсказок миллионов пользователей по игровым префиксам без API-ключей.
  2. *Unsupervised N-Gram Extractor*: статистический анализ названий игр в чартах Roblox Explore API с расчетом дельты частотности относительно прошлых снимков. Если биграмма/триграмма внезапно взлетает у 3+ несвязанных игр, алгоритм автоматически регистрирует тренд.
  3. *Reddit JSON API*: выявление всплесков виральности в игровых сообществах до их выхода в массовые чарты.
  4. *Dynamic Memes Cache (`data/dynamic_memes.json`)*: единый самообновляемый файл состояния, подгружаемый анализаторами на лету.

## 6. Алгоритм поиска арбитражных ниш (Roblox ➔ Яндекс Игры)

- **Проблема сопоставления разноязычных каталогов:**
  Roblox оперирует англоязычными названиями (`Steal An Egg`, `Escape The Carnival`, `Toilet Tower Defense`), тогда как каталог Яндекс Игр наполнен русскоязычными карточками (`Укради яйцо`, `Побег из цирка`). Прямое строковое сравнение (Levenshtein / Jaccard на сырых строках) дает 0% схожести даже для идентичных клонов.
- **Инженерное решение (Двуязычный семантический сопоставитель):**
  1. *Нормализация:* Удаление квадратных/круглых скобок (`[X10]`, `[UPDATE]`, `[ALPHA]`), разделителей подзаголовков (`|`, `—`, `~`, `:`), а также эмодзи через свойство `\p{Extended_Pictographic}` с сохранением чисел 0-9 (критично для названий вида `99 Nights in the Forest` или `Pet Simulator 99`).
  2. *Словарь канонических концептов (`CONCEPT_DICTIONARY`):* Модуль сопоставляет ключевые игровые термины (воровство предметов `steal_item` ↔ `укради`/`воруй`, яйца `egg` ↔ `яйцо`, рэгдолл `ragdoll` ↔ `манекен`/`кукла`, переломы `break_bones` ↔ `сломай`/`кости`, хоррор `doors`/`night`/`forest` ↔ `двери`/`ночь`/`лес`).
  3. *Многофакторный скоринг схожести:* Взвешенная сумма схожести понятий (70%), биграммного коэффициента Дайса (20%) и бонуса за совпадение архетипа (10%). При несовпадении базового архетипа схожесть штрафуется вдвое (50%).
- **Пороги детекции:**
  - `minRobloxCCU`: 100,000 игроков (отсекает мелкие инди-эксперименты, гарантирует подтвержденный спрос).
  - `similarityThreshold`: 0.40 (если схожесть лучшего аналога в топ-100 Яндекс Игр < 0.40, фиксируется арбитражная ниша).
  - `topYandexLimit`: 100 карточек каталога.
- **Генерация арбитражных рекомендаций и бейджа `ARBITRAGE OPPORTUNITY`:**
  Для каждого обнаруженного разрыва алгоритм синтезирует:
  - Рекомендуемое русское название (SEO-оптимизированное для поиска Яндекса);
  - Рецепт адаптации под веб (Rewarded Video, мобильная верстка, легкий стек Vite/Canvas или Unity WebGL < 15 МБ);
  - Оценку потенциала первого хода (`CRITICAL_FIRST_MOVER` при CCU > 500k, `VERY_HIGH` при CCU > 200k, `HIGH` при CCU > 100k);
  - Интеграцию бейджа в сводную матрицу скоринга и заголовок Markdown отчета.
