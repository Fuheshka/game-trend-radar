# Implementation Notes: Game Trend Radar

> [!abstract] Паттерн ведения заметок реализации (Thariq / Anthropic Pattern)
> Документ фиксирует инженерные решения, технические компромиссы, ограничения внешних API и архитектурные развилки в процессе разработки.

---

## 1. Выбор архитектуры коллекторов данных

- **Проблема:** Браузерные движки (Puppeteer / Playwright) потребляют от 150 до 400 МБ памяти на каждый запуск, требуют бинарников Chromium и медленно стартуют в фоновых CLI задачах.
- **Решение:** Максимальный упор на легковесные прямые HTTP-запросы через нативный `fetch` (Node.js 20+).
  - *Roblox:* использование официального публичного Explore API (`apis.roblox.com/explore-api/v1/get-sort-content`), отдающего 100 игр с реальным CCU за ~300мс.
  - *Яндекс Игры:* парсинг SSR HTML каталога (`https://yandex.ru/games/`) через быстрые регулярные выражения и потоковый парсинг без загрузки тяжелых JS-бандлов.
  - *Poki:* парсинг HTML чарта `poki.com/en/popular`.
- **Компромисс:** Для YouTube Shorts в условиях сетевых ограничений и блокировок применяется отказоустойчивый режим (fallback-анализ метаданных и трендовых поисковых срезов без жесткого требования к постоянному стриму видео).

---

## 2. Скоринговая модель (Opportunity Score)

- **Почему линейный скоринг не работает:** Простая сумма баллов приводит к тому, что старые игры с миллионами установок (но перегретым рынком) получают высший приоритет, толкая разработчика в «красный океан».
- **Решение:** Дробно-рациональная формула, где в знаменателе стоит **Индекс насыщенности (Saturation Index)** и **Трудоемкость (Production Effort)**. Любой жанр с высокой конкуренцией или завышенной сложностью сборки резко штрафуется в итоговом рейтинге.

---

## 3. Версионирование и снимки рынка (Snapshots)

- Снимки сохраняются в `data/snapshots/snapshot-YYYY-MM-DD.json`.
- Это позволяет сравнивать дельту между замерами:
  - Какие игры выросли по онлайну за неделю.
  - Какие новинки ворвались в топ и сохраняют удержание.
  - Какие жанры теряют позиции.

---

## 4. Живое сканирование YouTube Shorts и детекция вирусных мемов

- **Двухуровневый сбор данных (Invidious + YouTube Data API v3):**
  - Приоритет отдается публичным инстансам Invidious (`inv.tux.pizza`, `invidious.nerdvpn.de` и др.), что исключает необходимость обязательной выдачи платных или лимитированных API-ключей Google Cloud.
  - При наличии `YOUTUBE_API_KEY` модуль автоматически задействует официальный YouTube Data API v3 (`search` + `videos.statistics`).
  - Реализован строгий тайм-аут запросов (`AbortController` на 6000мс) и автоматический перебор зеркал при сетевых ошибках или HTTP 5xx.
  - Бесшовный fallback на локальный курируемый датасет при полном отсутствии сети или блокировках.
- **Детекция вирусных сущностей:**
  - Библиотека регулярных выражений (`VIRAL_MEME_DEFINITIONS`) покрывает ключевые мета-тренды:
    - *Skibidi Toilet / Cameraman* (Roblox/Sandbox)
    - *The Amazing Digital Circus* (Pomni, Jax, Caine)
    - *Brainrot / Sigma / Rizz* (Only in Ohio, Mewing, Gigachad)
    - *Steal An Egg / Catch & Run* (Escape & incremental runner)
- **Расчет коэффициента вирусного ускорения (Viral Multiplier):**
  - Значение масштабируется от `1.0` (нейтрально) до `2.5` (сверхвирусный всплеск).
  - Учитывает частоту появления мемов в выборке и среднее число просмотров роликов.
  - Передается в `OpportunityScorer` для мультипликативного ускорения `velocityScore` и итогового скора перспективности жанра.

## 5. Стратегия полной автоматизации мониторинга (Zero-Maintenance)

- **Проблема зависимости от хардкода:** Зашивание регулярных выражений в код требует постоянного ручного вмешательства разработчика при появлении каждого нового интернет-мема.
- **Архитектурное решение (Спринт 6):**
  1. *YouTube Search Autocomplete API*: прямой опрос поисковых подсказок миллионов пользователей по игровым префиксам без API-ключей.
  2. *Unsupervised N-Gram Extractor*: статистический анализ названий игр в чартах Roblox Explore API с расчетом дельты частотности относительно прошлых снимков. Если биграмма/триграмма внезапно взлетает у 3+ несвязанных игр, алгоритм автоматически регистрирует тренд.
  3. *Reddit JSON API*: выявление всплесков виральности в игровых сообществах до их выхода в массовые чарты.
  4. *Dynamic Memes Cache (`data/dynamic_memes.json`)*: единый самообновляемый файл состояния, подгружаемый анализаторами на лету.

## 6. Алгоритм поиска арбитражных ниш (Roblox ➔ Яндекс Игры)

- **Проблема сопоставления разноязычных каталогов:**
  Roblox оперирует англоязычными названиями (`Steal An Egg`, `Escape The Carnival`, `Toilet Tower Defense`), тогда как каталог Яндекс Игр наполнен русскоязычными карточками (`Укради яйцо`, `Побег из цирка`). Прямое строковое сравнение (Levenshtein / Jaccard на сырых строках) дает 0% схожести даже для идентичных клонов.
- **Инженерное решение (Двуязычный семантический сопоставитель):**
  1. *Нормализация:* Удаление квадратных/круглых скобок (`[X10]`, `[UPDATE]`, `[ALPHA]`), разделителей подзаголовков (`|`, `—`, `~`, `:`), а также эмодзи через свойство `\p{Extended_Pictographic}` с сохранением чисел 0-9 (критично для названий вида `99 Nights in the Forest` или `Pet Simulator 99`).
  2. *Словарь канонических концептов (`CONCEPT_DICTIONARY`):* Модуль сопоставляет ключевые игровые термины (воровство предметов `steal_item` ↔ `укради`/`воруй`, яйца `egg` ↔ `яйцо`, рэгдолл `ragdoll` ↔ `манекен`/`кукла`, переломы `break_bones` ↔ `сломай`/`кости`, хоррор `doors`/`night`/`forest` ↔ `двери`/`ночь`/`лес`).
  3. *Многофакторный скоринг схожести:* Взвешенная сумма схожести понятий (70%), биграммного коэффициента Дайса (20%) и бонуса за совпадение архетипа (10%). При несовпадении базового архетипа схожесть штрафуется вдвое (50%).
- **Пороги детекции:**
  - `minRobloxCCU`: 100,000 игроков (отсекает мелкие инди-эксперименты, гарантирует подтвержденный спрос).
  - `similarityThreshold`: 0.40 (если схожесть лучшего аналога в топ-100 Яндекс Игр < 0.40, фиксируется арбитражная ниша).
  - `topYandexLimit`: 100 карточек каталога.
- **Генерация арбитражных рекомендаций и бейджа `ARBITRAGE OPPORTUNITY`:**
  Для каждого обнаруженного разрыва алгоритм синтезирует:
  - Рекомендуемое русское название (SEO-оптимизированное для поиска Яндекса);
  - Рецепт адаптации под веб (Rewarded Video, мобильная верстка, легкий стек Vite/Canvas или Unity WebGL < 15 МБ);
  - Оценку потенциала первого хода (`CRITICAL_FIRST_MOVER` при CCU > 500k, `VERY_HIGH` при CCU > 200k, `HIGH` при CCU > 100k);
  - Интеграцию бейджа в сводную матрицу скоринга и заголовок Markdown отчета.

## 7. Локальный HTTP-сервер для отдачи данных в UI (Порт 4200)

- **Архитектурный выбор (Ponytail / Zero-Dependency):**
  Сервер реализован на нативном `node:http` без сторонних тяжелых веб-фреймворков (Express/Fastify/Nest). Это обеспечивает:
  - Нулевой оверхед по памяти и зависимостям;
  - Мгновенный запуск и полную совместимость с `tsx` и `vitest`;
  - 100% контроль над заголовками CORS и потоками отдачи статики.
- **Маршрутизация и API эндпоинты:**
  1. `GET /api/snapshots/latest`: Отдает последний `MarketSnapshot` в формате JSON со всеми играми, вердиктами и арбитражными нишами. Если снимков еще нет — возвращает 404 с рекомендацией запустить сканирование.
  2. `GET /api/verdicts`: Отдает актуальный список вердиктов (`MarketVerdict[]`) с распределением статусов (🟢 Green / 🟡 Yellow / 🔴 Red), Opportunity Score, кор-лупами и стратегиями монетизации.
  3. `POST /api/scan`: Инициирует живое сканирование витрин (Roblox, Яндекс Игры, Poki, YouTube Shorts), сохраняет снимок и Markdown-отчет через `SnapshotStore`, и возвращает готовый снимок.
  4. `In-Flight Mutex Lock`: Защита от параллельных дублирующих сканирований — если сканирование уже идет, повторный запрос ожидает завершения текущего промиса `activeScanPromise`, предотвращая перегрузку внешних API и гонки записи файлов.
- **CORS и безопасность:**
  - Полная поддержка CORS Preflight (`OPTIONS 204 No Content` с заголовками `Access-Control-Allow-Origin: *`, методами и заголовками).
  - Защита от Path Traversal: нормализация `pathname` и строгая проверка `targetPath.startsWith(staticDir)` с возвратом `403 Access Denied`.
- **Раздача статики и SPA Fallback:**
  - Корневая папка статики: `web/dist` (при наличии собранного Vite-бандла) с fallback на `web/`.
  - Поддержка MIME-типов для HTML, CSS, JS/MJS, JSON, SVG, PNG, шрифтов.
  - Умный SPA fallback: отдает `index.html` только для HTML-запросов без расширений файлов, предотвращая ошибочные 200 ответы на отсутствующие статические ассеты.
  - Информативная темная страница-заглушка при обращении к `/`, если директория `web/` еще пуста.

## 8. Интерактивный клиентский веб-дашборд на Vite (Komorebi Dark)

- **Дизайн-система Komorebi Dark:**
  - Глубокая темная графитовая база (`#0a0b10`, `#101117`, `#151620`, `#1c1e2b`).
  - Неоновые семантические акценты статусов:
    - 🟢 *Green Light* (`#10b981`, изумрудный неон / высокий приоритет);
    - 🟡 *Yellow Light* (`#f59e0b`, янтарный неон / средний приоритет с уникальным хуком);
    - 🔴 *Red Light* (`#ef4444`, коралловый неон / перенасыщенный рынок);
    - ⚡ *Arbitrage Opportunity* (`#cba6f7`, лавандово-аметистовый бейдж).
  - Шрифты: JetBrains Mono для числовых значений и таблиц, Inter для текста и заголовков.
- **Интерактивная диаграмма RadarChart (Zero-Dependency SVG):**
  - Поддержка двух режимов визуализации:
    1. *Spider Radar*: многоосевая радиальная паутина по 5 осям (Скоринг, Спрос, Динамика, Монетизация, Свобода ниши);
    2. *Polar Donut*: секторное распределение CCU аудитории и рыночных долей.
  - Интерактивный плавающий тултип с метаданными при наведении курсора.
  - Клик по сегменту или элементу легенды фильтрует карточки вердиктов по выбранному архетипу.
- **Карточки вердиктов (`VerdictCards`):**
  - Круговой радиальный индикатор Opportunity Score (0-100).
  - Наглядная декомпозиция математической формулы с факторами Спроса, Динамики, Монетизации, Насыщенности и Трудоемкости, а также вирусным множителем YouTube Shorts.
  - Разбор шагов Core Loop со стилизованными стрелками (`Шаг 1 ➔ Шаг 2 ➔ Шаг 3`).
  - Акцентный блок рисков «Чего избегать» с предупреждающей индикацией.
  - Стратегии монетизации и интерактивные теги игр-образцов.
- **Фильтрация, сортировка и живой поиск:**
  - Фильтры по витринам: Roblox, Яндекс Игры, Poki, YouTube Shorts.
  - Фильтры по статусам: Green, Yellow, Red, только арбитраж.
  - Сортировка по скору, онлайну (CCU), скорости и названию.
  - Живой поиск с поддержкой горячей клавиши `Cmd/Ctrl + K`.
- **Живое сканирование рынка:**
  - Кнопка в шапке с неоновым свечением.
  - Пошаговое модальное окно прогресса со сменяющимися фазами сбора данных и расчетом скоринга.
  - Защита от сбоев: бесшовный fallback на встроенный эталонный снапшот при отсутствии связи с сервером.

## Единая команда запуска веб-интерфейса и GitHub Pages

- **Автоматическое открытие браузера (`openBrowser`):**
  - Реализован кроссплатформенный запуск системного браузера (macOS: `open`, Windows: `start`, Linux: `xdg-open`) на базе стандартного модуля `node:child_process` без сторонних зависимостей (YAGNI & Ponytail).
  - Защита тестового контура: открытие браузера автоматически блокируется в окружении Vitest и CI (`process.env.CI`, `process.env.VITEST`).
  - Graceful handling порта `EADDRINUSE`: если сервер уже запущен в фоновом терминале, процесс не падает с ошибкой, а выводит информацию о работающем дашборде и открывает браузер.
- **Информативный терминальный вывод:**
  - Оформлен компактный блок запуска в стиле Vite / Next.js с кликабельными ссылками на локальный дашборд (`http://localhost:4200/`), API-эндпоинт (`/api/snapshots/latest`) и указанием активного клиентского бандла.
- **Скрипт `scripts/open_ui.ts`:**
  - Автономная точка входа, проверяющая активность сервера по HTTP перед стартом. При уже запущенном сервере мгновенно открывает браузер и завершает процесс без конфликтов портов.
- **Деплой на GitHub Pages (`.github/workflows/deploy-pages.yml`):**
  - Подготовлен пайплайн GitHub Actions для автоматической сборки (`npm run web:build`) и публикации статического дашборда на GitHub Pages.
  - Плагин `copy-latest-snapshot` в `vite.config.ts` при сборке копирует свежий снимок рынка в `web/dist/data/latest_snapshot.json`.
  - В клиенте `web/src/main.ts` добавлен многоуровневый fallback: при недоступности Node.js бэкенда дашборд сначала пробует загрузить статический `latest_snapshot.json`, а затем переходит на встроенную эталонную модель `FALLBACK_SNAPSHOT`.

## 7. Дорожная карта оживления веб-интерфейса (Revitalization Plan)

- **Диагностика:** Выявлена проблема «мертвого» дашборда — в то время как парсеры собирают 473 реальные игры и детальные арбитражные связки, интерфейс отображает только 8 текстовых карточек архетипов и статичный SVG-полигон без динамики.
- **Инженерный план решения:** Сформирован канонический файл `prompts-roadmap.md` из 12 атомарных задач по 4 этапам:
  1. *Визуал и Game Feel:* сканирующий луч радара (sweep-beam), пульсирующие точки (blips), плавные счетчики метрик (count-up), бегущая строка трендов (Live Ticker), синтез тактильных звуков через Web Audio API.
  2. *Каталог 473 игр и Drawer:* боковая шторка с деталями игры/архетипа, прямой каталог всех 473 игр с ссылками на витрины, быстрые теги поиска.
  3. *Матрица арбитража:* наглядное сопоставление рынков (Roblox vs Яндекс Игры vs Poki), окно возможностей, экспорт питч-карточек.
  4. *Инструменты и история:* генератор GDD-промптов для ИИ, селектор исторических снимков с динамикой трендов, экспорт в Markdown/JSON.

## 8. Автоматический сбор поисковых запросов YouTube Autocomplete и Invidious Gaming

- **Модуль `YouTubeAutocompleteHarvester` (`src/collectors/youtube_autocomplete.ts`):**
  - Реализован класс сбора подсказок и суточных трендов без необходимости ввода ключей API Google.
  - По умолчанию опрашивает префиксы: `'roblox '`, `'shorts roblox '`, `'роблокс '`, `'game dev shorts '`, `'simulator roblox '` через эндпоинт `suggestqueries.google.com/complete/search?client=youtube&ds=yt&q={prefix}`.
  - Поддерживает парсинг как чистого JSON, так и JSONP формата (`window.google.ac.h(...)`), удаление HTML-тегов (`<b>...</b>`), нормализацию регистра и дедупликацию поисковых запросов.
  - Метод `extractSuffix` автоматически отделяет префикс от растущего поискового суффикса (например, `'roblox '` -> `'steal time simulator'`).
- **Сбор суточных трендов Invidious Gaming (`fetchTrendingGamingVideos`):**
  - Опрашивает `/api/v1/trending?type=gaming` для извлечения топ-50 игровых видео суток.
  - Ротация публичных зеркал Invidious (`DEFAULT_INVIDIOUS_INSTANCES`) при недоступности или HTTP 5xx.
  - Защита таймаутом 5000 мс через `AbortController` на каждый запрос.
  - Структурированный возврат данных без падения процесса и утечек ошибок.
- **Тестирование (TDD & Vitest):**
  - Создан полный набор тестов `tests/YouTubeAutocomplete.test.ts` (12 тестов, 100% pass), проверяющий работу парсера, очистку тегов, дедупликацию, отказоустойчивость и ротацию зеркал.

## 9. Автоматическое обнаружение новых трендов и мемов без словаря (Unsupervised Trend Extraction)

- **Модуль `UnsupervisedTrendExtractor` (`src/analyzer/trend_extractor.ts`):**
  - Реализован класс алгоритмического поиска зарождающихся мемов и игровых механик в чартах Roblox и YouTube Shorts без использования жестко заданных словарей ключевых слов.
  - **Очистка названий от рекламного шума (`cleanTitle`):**
    - Удаление квадратных скобок с рекламными тегами (`[UPDATE]`, `[NEW]`, `[X10]`, `[ALPHA]`).
    - Удаление эмодзи и вариационных селекторов через `\p{Extended_Pictographic}|\uFE0F|\uFE0E`.
    - Очистка круглых скобок, пунктуации и спецсимволов с сохранением текстового контекста названий.
  - **Токенизация и построение N-грамм (`extractNgrams`):**
    - Построение биграмм (2 слова) и триграмм (3 слова).
    - Агрегация частотности (число уникальных игр на N-грамму) и суммарного онлайн-потока CCU (`metricValue`).
  - **Детекция аномалий роста (Velocity Spike):**
    - Сравнение распределения частот N-грамм с предыдущим снимком рынка (снапшотом из `data/snapshots/` или переданным в параметрах).
    - Автоматическая регистрация тренда при выполнении двух условий:
      1. N-грамма встречается в **3+ разных играх** (`currentFrequency >= 3`).
      2. Частота выросла в **2.5+ раза** по сравнению с предыдущим снимком (`growthVelocity >= 2.5` либо появление с нуля `0 -> 3+`).
  - **Автоматическое связывание с архетипами:**
